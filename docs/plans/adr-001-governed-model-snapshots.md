# ADR 001：以不可变模型快照引入受治理指标

- 状态：已采用
- 日期：2026-11-11
- 更新：2026-11-13，默认开启受治理运行时并接入 Chat
- 上游基线：`fc43a82600e18b19d159c52023f54f5572f537ac`
- 规划：[语义层增强任务书](auto-ontology-semantic-layer-plan.md)

## 决策与原因

在 Auto Ontology 内新增 `GovernedModel`。每个版本包含完整的来源、字段、关系和指标定义，经 Pydantic 闭合结构校验后持久化。模型身份和版本记录使用关系表；内容以受校验的 JSON 快照保存，不允许任意 JSON 直接进入运行时。

指标、来源、关系在模型内保有稳定 ID，但第一版以**模型修订版**作为发布和认证单元。指标内容、完整模型和查询请求分别生成确定性指纹。复合指标的引用在同一个不可变快照内解析，因此不会在查询时混入另一个版本的依赖。

这样可以先交付一致的运行时闭环，避免一开始就引入跨模型版本求解和部分发布。代价是修改一个指标也需要重新审核并发布整个模型；当前不提供指标级独立发布。后续可以增加跨模型固定版本引用，不能把当前快照中的引用改成“自动读取最新版”。

## 运行路径

1. 现有 Catalog 和 Term 保持真实资产身份。
2. 编辑者保存一个模型草稿；修改产生新的不可变修订版。
3. 服务检查静态契约与实际 Catalog 绑定，审核者提供认证依据。
4. 发布时固定已认证修订版；并发更新必须携带期望版本。
5. 结构化请求和自然语言解析产物进入同一编译器。
6. PostgreSQL 连接器接收 SQL 和独立参数字典，执行时再次检查治理状态及绑定。

已发布旧修订版不会因为新草稿存在而自动失去认证。主动弃用或依赖结构不兼容应阻止执行。历史审核证据仍保留。

## 与原有能力的关系

新增 `/metrics` 管理和查询入口，复用现有 Next.js 权限代理、FastAPI、SQLAlchemy Core、Alembic 与 PostgreSQL 连接器。Chat 提供显式的标准指标模式，使用所选已认证模型；探索模式保留原有 Text-to-SQL 流程。两种路径在会话状态与结果中分别标记，不将探索性 Chat 的结果冒充契约执行结果。

标准指标解析只返回结构化请求或澄清/错误，不直接生成 SQL。工作台在用户执行后调用共享服务；Chat 在解析为可执行请求后，在同一轮调用共享校验、编译和执行服务。需要澄清时可在会话中继续回答，语义上下文从该用户拥有的服务端历史读取，并绑定模型版本与指纹；校验失败后不自动改走探索性 SQL。

运行时默认开启，显式关闭开关仍可停用查询并保留治理数据。默认值不改变权限和认证条件；草稿预览仍要求编辑权限并标记未认证。实际模型调用、本地集成测试和生产业务验收分别记录，自动化测试不代表业务认证。

历史 SQL 提炼仍生成 `SqlAttribute` 候选。完整查询可保留复杂语义，但并不因此成为可编译的 Metric。将历史 SQL 转为指标契约，需要补齐来源、粒度、谓词、单位和时间含义后审核。

## 范围约束

- 首版标准指标运行时仅支持 PostgreSQL。
- 表达式采用受限 AST；允许字段、常量、指标引用和四则运算，服务端不接受任意 SQL 片段作为指标公式。
- 支持单一事实行粒度及不会放大该粒度的维度连接。
- 同一事实的替代来源需要满足相同语义及请求能力，优先级仅用于合格候选之间的选择。
- 多事实联算、预聚合自动改写、窗口表达式和不安全的扇出应明确拒绝。
- 普通导入创建草稿；导入包携带的认证元数据不能赋予执行权限。
- 外部 Ossie/RDF 格式不负责承载本扩展；使用专用原生 JSON 导出，避免静默丢失契约字段。
