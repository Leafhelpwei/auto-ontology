## 批次 1：通用模型与失败处理

- 所有模型统一为单个首部系统消息；证据、字段和值锚点保持用户数据角色。
- 显式模型、端点与能力配置；通用 API key 不再自动选择 Claude 或推断中转端点。
- SDK 自带重试关闭，统一最多 3 次调用、总时限包含并发排队；仅瞬时错误允许同端点/明确允许的端点回退。
- 结构化输出缺失或无效进入有限纠正，拒答/认证/配置错误不改投其他服务。
- 意图校验失败不放行 SQL；不返回曾被意图校验拒绝的 SQL；上下文解析不可用时要求重述完整问题。
- 实际 OpenAI-compatible 与 NVIDIA SDK 连接本地 HTTP 服务验证消息及结构化协议。该验证不代表真实供应商效果、真实生产数据或完整登录业务链路已验收。

## 批次 2：身份、连接凭据、MySQL TLS

- SSO 必须通过真实签名验证、issuer / audience / exp / iat / sub 检查和精确 provider+subject 本地绑定；无邮箱权限回退；各登录入口重新读取本地封禁/角色状态。
- 连接输入按数据库类型限制可写字段，公共响应只输出白名单字段；内部运行时 token 不能经公开 API 保存，既有未知秘密字段不会出现在读取结果中。
- MySQL 默认校验 CA 与主机身份。UI 和 URI 支持 `VERIFY_IDENTITY`、`VERIFY_CA`、显式开发明文 `DISABLED`。不忽略未知参数或互相冲突的配置。
- 密码、私钥和口令不修剪空白；空字段保留旧值，`clear_secret_fields` 显式清空。连接测试结果与表单版本绑定，旧结果不能批准新凭据。
- 本地隔离 MySQL Community 5.7.44 已实测正确 CA、错误 CA、错误主机名、缺少受信 CA、明文拒绝、只读快照、取消及数值/Unicode 路径。未连接用户生产库。
- 前端使用真实 JOSE 签名验证和组件事件回归；完整真实 SSO 登录/生产身份仍待验收。

## 批次 3：Chat 请求隔离与工作进程生命周期

- 输入/输出均绑定服务器生成的 request ID；ERROR、错配消息、异常退出和请求超时会淘汰工作进程，不能复用遗留 DONE 或其他用户结果。
- 会话互斥、每用户运行数和总运行数在创建工作进程之前检查。完成但尚未释放的任务仍保留互斥，断开浏览器不会隐式抢占。
- 初始化有独立时限和 READY 检查；失败返回 503。全局进程容量包含预热进程，队列和单条 IPC 消息有上限。
- 取消、初始化期间取消、刷新配置、停机、父进程 SIGKILL 均有资源回收路径；本地 generation 阻止旧配置进程重新入池。跨副本 generation 和运行状态仍待实现。
- 使用实际 spawn 子进程验证不同用户/token 的 A/B/C 隔离、错误后的旧 DONE、错配 ID、突然退出、启动/请求超时、并发拒绝、句柄回收及父进程死亡；未用这些结果替代真实 SSO/生产验收。

运行预算可通过 `CHAT_MAX_WORKERS`（默认 4）、`CHAT_MAX_RUNS_PER_USER`（默认 2）、`CHAT_WORKER_STARTUP_TIMEOUT_S`（默认 60）、`CHAT_REQUEST_TIMEOUT_S`（默认 180）和 `CHAT_MAX_EVENT_BYTES`（默认 2097152）调整。仍需完成查询结果流式预算及共享运行存储。

## 批次 4：共享运行状态、重放与跨实例配置版本

- 通过新增 Alembic revision 8704a3c4ca74 建立持久化运行记录、租约和带序号事件日志；全局/用户配额及会话独占在分配进程前由数据库协调。
- 双后端进程可相互观察与取消；执行副本 SIGKILL 后进入明确中断终态；租约失效后不能再写入事件或会话。
- 事件和对应历史消息在同一事务内提交；消息使用稳定 ID 防止重复。答案已落库后的失败保留答案并追加同样可重放的提示。
