## 批次 1：通用模型与失败处理

- 所有模型统一为单个首部系统消息；证据、字段和值锚点保持用户数据角色。
- 显式模型、端点与能力配置；通用 API key 不再自动选择 Claude 或推断中转端点。
- SDK 自带重试关闭，统一最多 3 次调用、总时限包含并发排队；仅瞬时错误允许同端点/明确允许的端点回退。
- 结构化输出缺失或无效进入有限纠正，拒答/认证/配置错误不改投其他服务。
- 意图校验失败不放行 SQL；不返回曾被意图校验拒绝的 SQL；上下文解析不可用时要求重述完整问题。
- 实际 OpenAI-compatible 与 NVIDIA SDK 连接本地 HTTP 服务验证消息及结构化协议。该验证不代表真实供应商效果、真实生产数据或完整登录业务链路已验收。

## 批次 2：身份、连接凭据、MySQL TLS

- SSO 必须通过真实签名验证、issuer / audience / exp / iat / sub 检查和精确 provider+subject 本地绑定；无邮箱权限回退；各登录入口重新读取本地封禁/角色状态。
- 连接输入按数据库类型限制可写字段，公共响应只输出白名单字段；内部运行时 token 不能经公开 API 保存，既有未知秘密字段不会出现在读取结果中。
- MySQL 默认校验 CA 与主机身份。UI 和 URI 支持 `VERIFY_IDENTITY`、`VERIFY_CA`、显式开发明文 `DISABLED`。不忽略未知参数或互相冲突的配置。
- 密码、私钥和口令不修剪空白；空字段保留旧值，`clear_secret_fields` 显式清空。连接测试结果与表单版本绑定，旧结果不能批准新凭据。
- 本地隔离 MySQL Community 5.7.44 已实测正确 CA、错误 CA、错误主机名、缺少受信 CA、明文拒绝、只读快照、取消及数值/Unicode 路径。未连接用户生产库。
- 前端使用真实 JOSE 签名验证和组件事件回归；完整真实 SSO 登录/生产身份仍待验收。
